# Техническое задание · Трекер расходов

[← К README](README.md)

## Рабочий сценарий
Пользователь в конце недели заносит чеки за продукты и транспорт, проверяет месячный итог и переносит записи на другой компьютер. Ошибка ручного ввода не должна менять список, а повреждённая копия файла не должна затереть ещё не сохранённые записи.

## Порядок реализации

1. Сделай разбор одной команды и ошибку использования. Затем реализуй хранение записей и присвоение ID.
2. Отдельно реализуй расчёт отчёта и порядок вывода. Добавь разбор суммы в копейках или точный десятичный расчёт.
3. Добавь экспорт, импорт и проверку целостности. Для импорта используй временное состояние, затем замени рабочее целиком.

## Контракт и контрольная сессия

Команды разделяются пробелами, регистр команд фиксирован, категория соответствует `[a-z][a-z0-9_-]{0,31}`. ID растут с 1, пропуски в загруженном файле допустимы; дубликаты и неверные поля отвергаются. `list` печатает `id date category amount` по строке на запись; пустой список выводит `EMPTY`. Сумма выводится с точкой и двумя знаками. Суммарное переполнение даёт явную ошибку.

| Шаг | Ввод | Что проверить |
| --- | --- | --- |
| 1 | `add 2026-01-15 food 100.10`, `add 2026-01-16 transport 49.90`, `add 2026-02-01 food 8.00` | ID 1, 2, 3; январский итог 150.00; февральский 8.00 |
| 2 | `add 2026-02-29 food 10.00` | Ошибка даты; `list` содержит три записи |
| 3 | `save`, новый запуск, `load` | Файл содержит три строки. Следующая корректная запись получает ID 4 |
| 4 | В копии CSV повтори ID в последней строке, выполни `load` на заполненной сессии | Ошибка с номером строки; отчёт и следующий ID остаются прежними |
| 5 | В новой рабочей папке вызови `load` без файла и `summary 2026-03` | Ошибка чтения без остановки программы, затем `TOTAL 0.00` |

К сдаче приложи исходники, команду запуска с JDK 21, пример CSV и вывод контрольной сессии.

## Функциональные требования

- [ ] `add <YYYY-MM-DD> <category> <amount>` добавляет расход и возвращает ID. Категория — одно слово, сумма — положительное число с точкой и максимум двумя знаками после неё.
- [ ] `list` выводит записи по ID. `summary <YYYY-MM>` выводит суммы по категориям в алфавитном порядке и общий итог. Пустой месяц даёт `0.00`.
- [ ] `save` сохраняет состояние в `expenses.csv`. `load` заменяет текущие записи после проверки всего файла и восстанавливает следующий ID. `exit` завершает программу.
- [ ] Неверная команда, дата или сумма дают понятную ошибку. При повреждённом файле сообщить номер строки и причину, сохранив текущие записи.

## Данные

Запись — уникальный положительный ID, дата, категория и сумма. Файл UTF‑8 без заголовка, например `1;2026-01-15;food;100.10`. Храни деньги в копейках (`long`) или в `BigDecimal`. Для хранения подойдут параллельные массивы.

## Пример ввода и вывода

```text
> add 2026-01-15 food 100.10
OK id=1
> add 2026-01-21 food 200.20
OK id=2
> summary 2026-01
food 300.30
TOTAL 300.30
> add 2026-01-21 food 0
ERROR amount: сумма должна быть больше нуля
> save
OK saved=2
```

## Нефункциональные требования

- [ ] Парсинг, расчёты и файловые операции разделены на методы. Сначала записывать во временный файл, чтобы ошибка записи оставляла прежний файл читаемым.
- [ ] В README указаны команда запуска из терминала и формат файла.

## Приёмка

- [ ] После перезапуска `load` и `summary 2026-01` возвращают тот же отчёт, следующий расход получает ID 3.
- [ ] Проверить пустой месяц, две категории, несуществующую дату и файл с плохой строкой после корректной.
